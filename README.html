Youtube Bilibili Digest

English | 简体中文  ·  Current version: 17.1.0

Turn every YouTube and Bilibili video into a resource for deep learning. Youtube Bilibili Digest brings transcripts, bilingual translation, AI overviews, explanations, and timestamped notes into one Chrome side panel, so you can study ideas and language without losing your place.

  • Turn captions into a readable, searchable learning resource, and copy or export them as plain text in whichever language mode you are viewing.
  • Learn languages with the original transcript, a Simplified Chinese translation, or an aligned bilingual view.
  • Build understanding with an AI overview, chapters, key quotes, and selected-text explanations — the overview has its own Original / 中文 / 双语 switch. The Original overview follows the language actually spoken in each part of the video: every chapter is written in the language spoken during that chapter's time range, so a video that switches language mid-way (for example a Chinese intro and an English interview) gets chapters in each part's language. The 中文 view translates only the non-Chinese chapters, keeping Chinese chapters verbatim at no cost, and the bilingual view is offered only when the overview is not entirely Chinese, skipping the duplicate line for chapters already in Chinese. After you adopt a foreign original transcript for an ai-zh video, the old overview is discarded and rebuilt from the new transcript the next time you open the Overview tab. Overview translation runs in batches, and any chapter it cannot translate is marked as untranslated rather than silently showing the source language.
  • Repair transcripts that arrived without punctuation using the AI 修复标点 action.
  • Navigate long videos by clicking timestamps in the transcript, overview, or notes, and let Follow playback keep the transcript scrolled to the current position.
  • Save polished timestamped notes for later study, filtered by This Video or All Notes, and open the notes view with the n key on the video page.
  • Export the whole video to Word — video info header, transcript, AI overview, and notes — as .doc or .docx.
  • Fall back to AI (ASR) subtitle generation when a video has no native captions.
  • Keep control of your data with your own AI endpoint, local Chrome storage, and no analytics or telemetry.

Youtube Bilibili Digest is a bring-your-own-endpoint project installed locally from GitHub. It is not available through the Chrome Web Store and does not run a developer-operated server.

Install manually

If you prefer to do it yourself:

  1. Choose a permanent folder and unzip or clone the project there. Optional suggestions are ~/Documents/youtube-bilibili-digest on macOS or Linux, or %USERPROFILE%\Documents\youtube-bilibili-digest on Windows. You may use a different folder.
  2. In Chrome, open chrome://extensions.
  3. Turn on Developer mode.
  4. Click Load unpacked.
  5. Select the exact project folder you chose, which must contain manifest.json.
  6. Pin Youtube Bilibili Digest from Chrome's Extensions menu if you want quick access.

Because this is an unpacked extension, it does not update automatically. After downloading an update or changing local files, click Reload on the Youtube Bilibili Digest card at chrome://extensions, then refresh open video tabs. Moving or deleting the source folder breaks the unpacked extension until you load it again from the new location.

Set up your AI endpoint

Youtube Bilibili Digest is bring-your-own-key throughout. YouTube captions are fetched through Supadata using a Supadata API key you enter in Settings; Bilibili subtitles are fetched directly with your browser's own Bilibili login and need no key. Your AI endpoint needs its own base URL and key.

The Settings page — opened from the side panel, or as the extension's Options page — is organised as cards, and its own interface can be switched between English and 中文 at the top:

  • Transcript provider: holds the Supadata API key for YouTube captions and the Enable Bilibili mode toggle (Bilibili captions come from the platform itself, no key).
  • AI provider: base URL, API key, and model name.
  • AI subtitle generation (ASR): the optional transcription fallback, off by default.
  • Local data: clear cached digests, delete all notes, or reset all extension data.
  • Local remix: a collapsed card with an editable prompt for adding a provider that is not OpenAI-compatible.

For AI features (overviews, explanations, translation, note polishing), configure any OpenAI-compatible Chat Completions endpoint in Settings:

  1. API base URL: the Chat Completions base URL of your provider. The default is Alibaba Cloud DashScope (Qwen):

text https://dashscope.aliyuncs.com/compatible-mode/v1

  1. API key: the key issued by your provider. For DashScope, create one in the Bailian console and paste it into Settings.
  2. Model: the model name your endpoint accepts, for example qwen-plus (the default), qwen-max, deepseek-chat, or gpt-4o-mini.

Open Settings from the side panel. You can also open the Youtube Bilibili Digest Options page from its card at chrome://extensions or by right-clicking its toolbar icon. Paste the key only into the Settings field. Never paste a key into an AI chat, repository file, screenshot, or public message.

Youtube Bilibili Digest sends every AI request in non-thinking mode where the gateway supports it, for responsive, predictable interactions. Keys and settings are stored in Chrome's local extension storage on your device. Release builds do not include or use config.js.

Enable Bilibili mode

Bilibili support is on by default and can be toggled in Settings:

  1. Sign in to bilibili.com in the same browser first. Bilibili only returns subtitles to logged-in accounts.
  2. Open a bilibili.com/video/... watch page. The Digest button and side panel work the same way as on YouTube.
  3. If a video has no subtitles or you are not logged in, the panel explains that instead of failing silently.

AI subtitle generation (ASR)

Videos without platform subtitles are no longer a dead end. In Settings, open the AI subtitle generation (ASR) card, tick the enable switch, and fill in the ASR endpoint, key (leave empty to reuse your AI API key), and model name (default qwen3-asr-flash).

When a video has no subtitles, the side panel offers a Generate AI Subtitles button. The extension downloads the video's audio track, resamples it in your browser, and sends it to your ASR endpoint in chunks; the generated transcript then flows through the same translation, overview, notes, and Word export pipeline. Timestamps of generated subtitles are approximate, and nothing is sent anywhere until you opt in.

The original-language transcript is transcribed by ASR straight from the video's own audio track. It is never a back-translation of the Chinese subtitles, so what you read is what the speaker actually said. Any non-Simplified-Chinese source language works (English, Japanese, Korean, French, German, Spanish, Russian, Portuguese, Italian, and more). In the Word export specifically, when a Bilibili video only offers the ai-zh Chinese AI subtitle track and you tick the original-language transcript, that original is produced through ASR as part of the export. The Transcript tab handles the same situation differently — see Bilibili videos with only Chinese AI subtitles below.

Two request protocols are available on the Settings page. The default is the DashScope/Qwen audio conversation protocol (chat/completions with qwen3-asr-flash), whose per-sentence timestamps are estimated by spreading each chunk over its duration. The alternative is the OpenAI/Groq-compatible Whisper multipart protocol (/audio/transcriptions), which returns the model's own real timestamps when the endpoint supports them. An optional source-language hint (for example en, ja, ko) can be filled in; leaving it empty lets the service auto-detect.

Limits that produce a visible error

These are hard-coded, and each one reports itself rather than failing silently:

  • Videos longer than 4 hours are refused for ASR.
  • Audio is resampled to 16 kHz mono and split into chunks of up to 180 seconds, with at most 4 chunks in flight and a 240-second timeout per request.
  • Chat-style AI requests (overview, explanation, translation, note polishing) abort after 50 seconds with no output or 120 seconds in total, and a response larger than 2 MiB is rejected.
  • The Word export path uses its own, more generous budget — 120 seconds idle, 300 seconds hard, 3 parallel workers, in chunks of about 7000 characters — because exports are long-running.
  • Export-time segment translation — a plain-text transcript exported in 中文 or 双语 mode, the bilingual Word document, and note translation — runs in batches of about 1800 characters with up to 5 batches in flight. A batch that is rate-limited, times out, or fails server-side is retried up to 3 times with exponential backoff, honouring a Retry-After header when the provider sends one; authentication errors are not retried. A batch that still fails leaves those segments untranslated rather than aborting the whole export. The side panel's live 中文 / 双语 transcript view uses a separate viewport-driven path and is unaffected.

Bilibili videos with only Chinese AI subtitles

Bilibili often publishes a single machine-generated Chinese track (ai-zh) for a video whose audio is another language. Left alone, the Transcript tab's Original view shows that Chinese machine translation and labels it Original (ai-zh).

This is handled in two steps:

  1. Free first, automatically. The initial subtitle request states no language preference, so Bilibili can return ai-zh even when the video also offers a free original-language track. When one exists, the extension re-requests it and switches over on its own. A platform track costs nothing, so no confirmation is needed.
  2. ASR only on your click. If there is no free original track, a notice appears above the transcript — with a matching 转写原文 button next to 修复标点 — explaining that the original can be transcribed from the audio. ASR is billed by audio duration and takes minutes, so it never runs by itself.

If the video looks genuinely Chinese, clicking says so (该视频为中文视频，无需额外转写) and stops instead of spending money. Detection reads the script of the video title, so a Chinese-titled English video is misjudged as Chinese; a 仍然转写 button appears in that case so you can override it.

Once an original has been adopted, the three modes split deliberately:

  • Original — the adopted original-language transcript. The badge reads ASR 生成 when it came from the audio.
  • 中文 — the platform's own ai-zh Chinese, shown verbatim. This costs nothing, which is why the platform track is kept rather than discarded.
  • 双语 — the adopted original paired with a fresh translation of it. This is the only mode that spends tokens here, and only when you open it. Its Chinese column therefore differs from the 中文 view: one is the platform's subtitle, the other is a translation of the original.

Both the adopted original and the platform Chinese are cached per video, so reopening the panel neither transcribes nor translates again.

Plain-text transcript export

The Export button on the Transcript tab writes a .txt file for whichever language mode you currently have selected, named after the video:

  • Original → Transcript_{title}_原文.txt
  • 中文 → Transcript_{title}_中文.txt
  • 双语 → Transcript_{title}_双语.txt, with each translation indented directly under its source line

Every file opens with a header carrying the title, channel, URL, and the exported mode, plus a Subtitle source: ASR 生成 line when the transcript was produced by ASR rather than read from the platform. The video's full description is included, so check the file before you share it.

Exporting Original is free — it writes what is already on screen. Exporting 中文 or 双语 translates the transcript through your AI endpoint, which costs tokens the first time. Segments already translated for the panel view are reused and the results are written back to the local cache, so a second export of the same video does not pay again. If no API key is configured, the button reports the failure rather than writing a half-translated file.

When the video's own transcript is already Chinese, all three modes would contain the same text, so the export collapses to a single Transcript_{title}.txt with no language suffix — the same rule the Word export applies.

Word document export

The Docs tab turns the current video into Word documents. Four content blocks are exported in a fixed order, each with its own switch:

  1. Video info header (on by default): title, platform, channel, link, duration, export time, subtitle source, and source language.
  2. Transcript body, optionally with per-sentence timestamps. Turning timestamps on switches the body to the punctuation-preserving channel, because AI paragraph merging destroys per-sentence timing.
  3. AI overview: chapters and key quotes.
  4. Timestamped notes: the notes you saved, with their transcript context. Notes are AI-translated when you export a Chinese or bilingual mode.

Three language modes can be exported at once, one file per mode: Original, 中文, and 原文·中文对照. The bilingual file aligns source and translation paragraph by paragraph using stable segment IDs, so a paragraph whose translation is missing prints an explicit grey placeholder instead of shifting every later pair out of alignment.

The Docs tab also lets you steer language detection directly. A 视频语言 selector (自动判断 / 原文（非中文） / 中文) overrides how the source language is decided, and an 原文语言 selector names it explicitly — 自动, or one of English, Japanese, Korean, French, German, Spanish, Russian, Portuguese, and Italian. Naming the language matters when ASR has to produce the original transcript, because it tells the transcription what to expect. After a successful export, a 📁 打开文件夹 button appears to open the download location.

Two file formats are offered:

  • .doc — Word-compatible HTML. The smallest output, the widest compatibility, and it works in any browser.
  • .docx — a real OOXML package. It relies on the browser's native CompressionStream (Chrome/Edge 103+). When the current browser does not support it, the export automatically falls back to .doc and says so in the summary area.

File names follow {title}_逐字稿_原文, {title}_逐字稿_中文, and {title}_逐字稿_对照. When the only product is the Chinese transcript of an already-Chinese source, the name stays {title}_逐字稿. The bilingual suffix was renamed from _中英对照 to _对照 on purpose: the source language is no longer assumed to be English.

Export can be cancelled at any time. Cancellation is cooperative — an ASR or translation chunk already in flight runs to completion and its result is then discarded. Cached segments are reused, so a second run does not pay for the same ASR or translation twice.

Use Youtube Bilibili Digest

  1. Open a standard YouTube watch page with captions, or a Bilibili video page while signed in.
  2. Click the Youtube Bilibili Digest extension icon to open the side panel. Two controls are also injected onto the player: the Digest button opens the panel, and the floating Note pill saves a note at the current playback position.
  3. Read the timestamped transcript, or choose Original, 中文, or 双语. Copy takes the transcript to your clipboard; Export saves Transcript_{title}_原文.txt (or the _中文 / _双语 form matching the mode you selected), which also embeds the video's full description — check it before you share the file.
  4. If a transcript arrived without punctuation, a 修复标点 button appears and rewrites it through your AI endpoint.
  5. Open Overview for AI-generated chapters and key quotes. It carries its own Original / 中文 / 双语 switch, independent of the transcript view.
  6. Select transcript text when you want an AI explanation.
  7. Save a note from the player or a key quote, then revisit it under Saved Notes, filtered by This Video or All Notes.
  8. Press n on the video page to save a note without reaching for the mouse. This deliberately overrides the platform's own n binding (on YouTube that is "next video"), and is ignored while you are typing in a field.
  9. Scroll away from the playback position and a Follow playback button appears; click it to jump back and resume auto-scrolling.
  10. Open the Docs tab to export everything to Word.

What works today

  • Google Chrome 116 or newer, using the Side Panel API.
  • Standard youtube.com/watch video pages and bilibili.com/video pages.
  • Native subtitle tracks (YouTube captions via Supadata, Bilibili subtitles read directly from the platform). In the transcript view the extension scores the available tracks and prefers human-authored ones, then Chinese or English, while penalising machine-generated (asr) and auto-translated tracks; it may still fall back to another native language. The Docs export path deliberately does the opposite and prefers a non-Chinese track, so the "original" transcript stays in the video's own language. Override either behaviour with the 视频语言 and 原文语言 selectors on the Docs tab.
  • Original, Simplified Chinese, and aligned bilingual transcript views.
  • AI overviews, selected-text explanations, translation, and automatic note polishing through any OpenAI-compatible endpoint you configure.
  • Local notes and a local cache for recent transcript and digest results.
  • Optional AI (ASR) subtitle generation for videos without native subtitles, using your own ASR endpoint.
  • Word export with a video info header, an optional per-sentence timestamp channel, the AI overview, and timestamped notes, as .doc or .docx, in original / Chinese / aligned bilingual modes.

Shorts, live streams, private or access-restricted videos, and videos without an available native transcript may not work. Firefox, Safari, mobile browsers, and other Chromium browsers are not currently tested or supported.

Youtube Bilibili Digest performs no local audio transcription. The optional ASR fallback sends audio only to the endpoint you configure, and only after you enable it in Settings.

AI usage costs

Transcript retrieval is free: it uses each platform's own caption endpoints. AI usage is billed by whichever OpenAI-compatible provider you configure. Costs depend on your provider's pricing, your chosen model, and how much you use overviews, explanations, translation, and note polishing. Translation is lazy and progressive: cached segments are reused, and only rows you scroll into view incur requests. The two exports are the exception — exporting a plain-text transcript in 中文 or 双语 mode, or generating a Word document, translates the whole transcript in one pass. Those results are cached, so repeating the same export costs nothing. Set spending limits in your provider account.

Youtube Bilibili Digest uses plain HTML, CSS, and JavaScript with no build step, so it is a friendly starting point for agent-assisted projects. Ideas to try:

  • Add personal topic filters that highlight the chapters most relevant to a goal.
  • Add optional local-model support for a different privacy and cost tradeoff.
  • Improve accessibility with keyboard navigation, font controls, and higher-contrast themes.

A note on internal naming (for those of you who read the code). Identifiers in the source keep the upstream YTD_ / ytd_ prefix (YTD_SETTINGS, ytd_notes, and similar). YTD is short for YouTube Digest, the name of the original project this one is derived from (by ZaraZhang); later features followed the same convention. These prefixes are internal only — renaming them would mean touching dozens of call sites, and a missed one fails silently. Everything user-facing says Youtube Bilibili Digest.

Ask your agent to preserve the bring-your-own-key model, keep secrets out of source files, work through the verification checklist below, and test the remix on real videos.

If you need a provider that does not follow the OpenAI Chat Completions API, first open the exact Youtube Bilibili Digest project folder that Chrome loaded through Load unpacked in your coding agent. Then open Youtube Bilibili Digest Settings, expand the collapsed Need a provider that is not OpenAI-compatible? card (listed under Local remix), and press Copy edited prompt. Replace the [PROVIDER] placeholder before sending it. Do not include any API key in the prompt or chat. After the agent updates your local copy, enter the key yourself in the Settings field it identifies.

Privacy and data flow

Youtube Bilibili Digest makes provider requests directly from the extension:

  1. It downloads captions from YouTube's own timedtext endpoints, or from Bilibili's subtitle and player APIs using your browser's login cookies. When you enable ASR, it also downloads the audio track from the platform's own media CDN — googlevideo.com for YouTube, the bilivideo hosts for Bilibili.
  2. It sends the transcript and relevant video metadata to the AI endpoint you configured when you request AI features.
  3. Focused features send only the content they need, such as selected text with context or small transcript batches for translation.
  4. It stores keys, settings, notes, and recent cache entries locally in Chrome.
  5. When ASR is enabled, audio chunks go only to the ASR endpoint you configured. The extension itself never uploads audio anywhere else and keeps no copy of it; the resulting text and timestamps are cached locally with the same 30-day expiry and 20-video limit.

There is no Youtube Bilibili Digest account system, advertising, analytics, or telemetry. Your configured AI provider still receives data under its own terms and privacy policy. See the privacy policy for details.

Troubleshooting

Cannot reach the video page

  • The extension could not talk to this tab's content script. Refresh the video tab and try again. The extension also re-injects its content script into the tab and retries once on its own.

Subtitle or audio requests come back empty

  • Play the video for a few seconds and try again: YouTube may not expose subtitle downloads or audio stream addresses before playback has started.
  • If it still fails, refresh the tab. Each subtitle request's HTTP status and body size is logged to the service-worker console, which pinpoints the cause.

The Digest button is missing on a YouTube video

  • At chrome://extensions, find Youtube Bilibili Digest and click Reload, then refresh the YouTube tab.
  • Confirm that you are on a standard https://www.youtube.com/watch?... page, not a Short, embed, or live page.
  • The current version automatically follows YouTube when its responsive action bar changes. Wait a moment after the page finishes loading.
  • If it is still missing, ask your coding agent to inspect the content script on that exact video page.

The side panel does not open

  • Confirm that you are on a standard https://www.youtube.com/watch?... page or a https://www.bilibili.com/video/... page.
  • At chrome://extensions, confirm Youtube Bilibili Digest is enabled and click Reload.
  • Refresh the video tab after reloading the extension.
  • Ask your coding agent to inspect the extension if the problem continues.

Youtube Bilibili Digest asks for setup

  • Open Settings and save an API base URL, API key, and model. The defaults point at Alibaba Cloud DashScope with qwen-plus; you only need to paste your key if you use DashScope.
  • If Settings says a legacy custom provider was removed, enter the three fields again. The old AI key was cleared so it could not be reused with the wrong service.

No transcript is found

  • Confirm the video is public and has native captions.
  • YouTube videos without captions cannot produce a native transcript. If you enabled AI subtitle generation (ASR) in Settings, the panel offers to transcribe the audio instead; otherwise configure the ASR card first.
  • For Bilibili, confirm you are signed in to bilibili.com in the same browser; subtitles are only returned for logged-in accounts, and many videos simply have no subtitles.

AI requests fail

  • A 401 or 403 usually means the API key is invalid for the configured base URL.
  • A 404 usually means the base URL or model name is wrong for your provider.
  • A 429 usually means a rate or spending limit was reached.
  • If you adapted a local copy for a non-compatible model, use the Settings customization prompt again and ask your coding agent to inspect that local implementation.

Never share API keys, private transcripts, or personal notes in chats, screenshots, or logs.

Checks for coding agents

This project has no build step, no package manager, and no test suite. The files in the repository are exactly what Chrome loads, so verification is manual. After changing the project, ask your coding agent to work through this checklist:

  1. Reload the unpacked extension at chrome://extensions and confirm the service worker registers with no errors.
  2. Open the developer tools console for the side panel, the options page, and a video page, and confirm nothing unexpected is logged.
  3. Confirm manifest.json still parses as valid JSON.
  4. Test one real YouTube video and one real Bilibili video end to end: transcript, translation, AI overview, a saved note, and a Word export.
  5. If you touched the ASR path, also test a video that has no native subtitles.
  6. If you edited a JavaScript file containing Chinese text, search it for stray curly quotes (“ ” ‘ ’) — one smart quote in place of a string delimiter breaks the service worker without an obvious error.

There is no automated substitute for these steps: only a live run proves that provider requests and platform interactions still work.
