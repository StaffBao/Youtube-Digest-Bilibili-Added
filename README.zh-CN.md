# Youtube Bilibili Digest

[English](README.md) | [简体中文](README.zh-CN.md) · 当前版本：**17.0.0**

把每个 YouTube 和 Bilibili 视频变成一份可以深入学习的资料：字幕、双语翻译、AI 概览、内容讲解和时间戳笔记，全部收进同一个 Chrome 侧边栏，让你持续学习视频中的知识和语言，同时不丢失原视频上下文。

这是一个**需要自行提供 AI 接口**的本地项目，通过 GitHub 安装。没有上架 Chrome 应用商店，也没有开发者运营的服务器。

> 完整文档：[README.zh-CN.html](README.zh-CN.html)（中文）· [README.html](README.html)（English）· [PRIVACY.html](PRIVACY.html)（隐私，英文版）· [SECURITY.md](SECURITY.md)

## 功能一览

- **字幕**：原文、简体中文翻译、双语对照三种视图，可一键复制，或把当前视图导出为 `Transcript_{标题}_原文.txt` / `_中文.txt` / `_双语.txt`。
- **AI 概览**：章节与重点引用，并有独立的 原文 / 中文 / 双语 切换。原文概览逐章采用该章时间范围内实际说的语言：视频中途换语言时（如中文开场 + 英文访谈），各章按各自片段的语言生成。中文 视图只翻译非中文章节、中文章节逐字保留（不花 token）；仅当概览非全中文时提供 双语，已是中文的章节不重复显示。为 ai-zh 视频采纳外文原文后，旧概览作废，下次打开概览页时按新字幕重生成。概览翻译按批进行；翻译不到的章节会标记 未翻译，而不是静默显示原文。
- **选中讲解**：选中字幕任意段落，获取 AI 解释。
- **时间戳笔记**：自动润色，可按 本视频 / 全部笔记 筛选；在视频页按 `n` 键即可记一条。
- **Word 导出**（`.doc` / `.docx`）：视频信息头 + 字幕正文 + AI 概览 + 笔记，支持原文、中文、原文·中文对照三种模式。
- **AI 字幕生成（ASR）**：无原生字幕时的兜底方案，默认关闭。
- **修复标点**：为缺标点的字幕一键补齐。
- **跟随播放**自动滚动，时间戳处处可点击跳转。
- 无分析统计、无行为追踪、无账号系统，密钥只保存在本地 Chrome 存储中。

## 安装

1. 把本仓库克隆或下载到一个长期保留的文件夹。
2. 在 Chrome 中打开 `chrome://extensions`，开启**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择包含 `manifest.json` 的那个文件夹。
4. 在侧边栏打开**设置**，填入 API 接口地址、API 密钥和模型名称。

请让这个文件夹留在原位——移动或删除它会让已加载的扩展失效，需要重新加载。每次更新后，请在扩展卡片上点击**重新加载**，并刷新已打开的视频页面。

需要 Chrome 116 或更高版本（Side Panel API）。仅支持标准 `youtube.com/watch` 与 `bilibili.com/video` 页面；Shorts、直播、私密或受限视频可能无法使用。

## 配置

设置页按卡片组织，页面顶部可在 English 与中文之间切换界面语言：

| 卡片 | 用途 |
|---|---|
| **字幕服务** | 填写 YouTube 字幕所用的 Supadata API Key，并包含**启用 Bilibili 模式**开关（Bilibili 字幕直接来自平台、无需 Key） |
| **AI 服务** | API 接口地址、API 密钥、模型名称 |
| **AI 字幕生成（ASR）** | 可选的转写兜底，默认关闭 |
| **本地数据** | 清除缓存摘要、删除全部笔记，或重置全部数据 |
| **本地改造** | 折叠卡片，内含可编辑提示词，用于接入非 OpenAI 兼容的服务 |

默认指向阿里云百炼 DashScope（Qwen）：

```
接口地址  https://dashscope.aliyuncs.com/compatible-mode/v1
模型      qwen-plus
```

任何 OpenAI 兼容的 Chat Completions 接口均可使用。使用 B 站前，请先在同一个浏览器登录 `bilibili.com`——字幕和音频流地址只对已登录账号返回。

> 请勿把 API 密钥发到聊天、issue、截图或源代码中，只在扩展的设置页面填写。

## AI 字幕生成（ASR）

视频没有原生字幕时，在设置页启用 ASR 卡片，侧边栏会出现**生成 AI 字幕**按钮。音频从平台自己的媒体 CDN 下载，在浏览器内重采样，再分块发送到你配置的 ASR 接口，结果直接进入翻译、概览、笔记和导出的同一条流水线。

支持两种请求协议：DashScope/Qwen 音频对话协议（`chat/completions`，默认，模型 `qwen3-asr-flash`）与 OpenAI/Groq 兼容的 Whisper `multipart` 协议（`/audio/transcriptions`）。默认协议的逐句时间戳为估算值；Whisper 协议在端点支持时返回模型自己的真实时间戳。

在你主动启用之前不会发送任何内容。原文逐字稿由 ASR 直接从视频音轨转写，不是把中文字幕回译。

### 会明确报错的限制

- 时长超过 **4 小时**的视频不执行 ASR。
- 音频重采样为 **16 kHz** 单声道，按最长 **180 秒**分片，最多 **4 片并发**，单次请求超时 **240 秒**。
- 对话式 AI 请求在 **50 秒**无输出或总计 **120 秒**后中止；响应超过 **2 MiB** 会被拒绝。
- Word 导出预算更宽松：空闲 **120 秒**、硬超时 **300 秒**、**3 路并发**、每块约 **7000** 字。
- 导出时的逐段翻译（以 中文 或 双语 模式导出纯文本逐字稿、生成对照 Word 文稿、笔记翻译）按每批约 **1800 字**切分，最多 **5 批并发**；被限速或失败的批次指数退避重试最多 **3 次**，并优先采用服务端 `Retry-After`。鉴权类错误不重试；仍然失败的批次只让该段保持未翻译，不会中断整次导出。侧边栏的 中文 / 双语 视图走另一条按视口懒加载的链路，不受影响。

### 只有中文 AI 字幕的 B 站视频

B 站经常只为外文音频的视频下发唯一的机器中文字幕轨（`ai-zh`）。如果该视频另有免费的原文字幕轨，插件会自动重新请求并切换过去——平台字幕不花钱。如果没有，字幕上方会出现提示条和 **转写原文** 按钮；ASR 按音频时长计费，因此绝不自动运行。判定为中文的视频只会得到提示而不会转写，同时提供 **仍然转写** 覆盖入口（判定依据是标题的文字体系，中文标题的外文视频会被误判）。

取得原文后：**Original** 显示原文，**中文** 原样显示平台的 `ai-zh` 字幕（免费），**双语** 以原文为源配一份新翻译——这是唯一花 token 的模式，且只在打开时才花。两份字幕都按视频缓存。

### 排障

- **无法与视频页通信** —— 扩展无法与该标签页的 content script 通信。请刷新视频标签页；扩展也会自动重新注入 content script 并重试一次。此错误态刻意不提供 ASR，因为 ASR 依赖同一个无法触达的页面状态。
- **字幕或音频请求返回空** —— 先播放视频几秒再重试：YouTube 在播放开始前可能不下发字幕下载或音频流地址。若仍失败请刷新标签页；每次字幕请求的 HTTP 状态码与响应体大小会记录在 service worker 控制台。

## 隐私速览

请求由扩展直接发往视频平台或你配置的接口，开发者不做代理、也不会收到这些请求。host 权限（`https://*/*`）仅用于访问：你的 AI 接口、你的 ASR 接口、YouTube 字幕所用的 Supadata 接口、B 站的字幕与播放器接口，以及——启用 ASR 时——平台自己的媒体 CDN（`googlevideo.com`、`bilivideo`）。设置、密钥、笔记和缓存都保存在 Chrome 本地：笔记上限 100 条，缓存上限 20 个视频、30 天过期。音频永不写入存储。以 中文 或 双语 模式导出纯文本逐字稿、或生成 Word 文稿时，会把整篇字幕一次性发送到你配置的 AI 接口翻译，而不只是你滚动经过的那几行；已翻译的分段会从本地缓存复用。完整说明见 [PRIVACY.html](PRIVACY.html)。

## 关于内部命名的说明（给会看代码的你）

源码中的标识符沿用了上游的 `YTD_` / `ytd_` 前缀（如 `YTD_SETTINGS`、`ytd_notes`）。`YTD` 是本项目所衍生的原版名称 *YouTube Digest* 的缩写（By ZaraZhang），后续新增功能也沿用了同一约定。这些前缀纯属内部使用，改名意味着要改动数十处，调用点漏掉一处还会静默失效。所有面向用户的名称均为 **Youtube Bilibili Digest**。

## 修改后的验证

本项目没有构建步骤、没有包管理器，也没有测试套件——仓库里的文件就是 Chrome 直接加载的内容，因此验证是手动的：

1. 重新加载已解压的扩展，确认 service worker 注册无报错。
2. 检查侧边栏、设置页和视频页的控制台输出。
3. 确认 `manifest.json` 仍是合法 JSON。
4. 在真实的 YouTube 视频和 B 站视频上各跑一遍完整流程：字幕、翻译、概览、笔记、Word 导出。
5. 如果改动了 ASR 相关代码，再测一个没有原生字幕的视频。
6. 修改含中文的 JavaScript 文件后，搜索是否混入弯引号（`“ ” ‘ ’`）——一个智能引号顶替字符串定界符，就会让 service worker 在没有明显报错的情况下失效。
